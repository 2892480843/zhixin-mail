# 知信 0.3.8 · 邮箱赛道决赛讲稿

**一句话：** 知信把需要行动的来信变成有原文依据、可编辑、由你审阅后执行的提案；同一事项的新变化继续更新同一张卡。

受众：评委与现场观众。下面的三分钟为排练建议，并非赛务规定。当前应用为 0.3.8，使用官方 RC6 的本机签名商店验证；公开发布与提交以 Release 和 #106 实际记录为准，初赛 79/100 属于 v0.2.1，不能当作新版评分。

## 三分钟分镜与口播

| 时间 | 画面与操作 | 口播要点 |
| --- | --- | --- |
| 0:00–0:20 | 收件箱、待确认入口 | “通知看到了，安排未必跟着改。知信专门处理来信里的下一步：什么变了、依据在哪、需要怎样回复。” |
| 0:20–0:55 | 学校通知详情，16:00 → 15:30、原文引用；展开完整原文 | “这里是时间变化的提案。模型给出的引用必须逐字命中正文，新旧值也必须出现在引用里；核对失败就隐藏对应变化值，保留原文供人核对。” |
| 0:55–1:30 | 编辑草稿；真实宿主中取消一次，再审阅批准 | “回复是可编辑草稿。发送须在宿主核对收件人、主题和正文，再由用户批准。取消会保留提案和草稿，规则也不能跳过审阅。” |
| 1:30–2:10 | 新补充通知，15:30 → 15:20；同卡重新待确认；再确认、日程板 | “刚确认又变了，应用更新原来的事项并重新等你确认，不另建一堆待办。再次确认后更新已有日程。日程板是应用内记录。” |
| 2:10–2:35 | 真实收件方回复、发送记录、桌面 glance 待办变化 | “明确接受回执后才记完成；发送记录保留本次准确提交正文。实际送达要在收件方核对。桌面卡只显示待办数，不展示邮件内容。” |
| 2:35–3:00 | 物流追踪、规则与撤销 | “同一订单的新通知更新同一份追踪。可以记住某个发件人的某类动作来准备草稿，也可以撤销。把重复整理交给应用，把确认留给人。” |

真实演示时使用专用测试账号和实际日期。准备第二个邮箱核对送达；宿主、模型、glance 的现场记录见 [REAL-HOST-DEMO.md](REAL-HOST-DEMO.md)。

## 无账号时的排练路径

1. 进入演示，点击「开始分步演示：先处理，再收到变化」。初始 4 封来信、3 项待确认。
2. 打开学校提案，查看 16:00 → 15:30 与原文，修改草稿，点击「演示确认（不发送）」。日程板出现 1 项。
3. 回收件箱，点击「模拟学校补充通知 →」。同卡变为第二次更新、15:30 → 15:20，并重新待确认。
4. 再确认，日程板仍为 1 项，内容更新为 15:20。
5. 回收件箱，点击「模拟物流送达通知 →」，打开订单追踪查看「已送达」。
6. 「发送记录」为空，演示没有冒充真实发送。刷新重置分步进度；保留的演示规则可在规则页撤销。

排练开场须说“接下来是内置演示数据”；其模型分析为预设，确认只更新演示状态。真实宿主审阅、送达与桌面卡片必须另录，不能用这一段替代。

## 答辩备答

| 可能的问题 | 准确回答 |
| --- | --- |
| 与邮件摘要有什么区别？ | 除了阅读，还把安排变化整理成提案、草稿和结果；后续通知继续更新同一事项。 |
| 怎么防止模型编造？ | 校验引用与具体提取值的字面来源，核对失败清除或隐藏对应值；草稿仍由人审阅。这降低无来源字段进入提案的风险，不保证全部语义正确。 |
| 能不能自动发送？ | 每次真实发送都需要宿主前台批准。发件人 + 动作规则只准备草稿，可以撤销。 |
| 接受回执等于送达吗？ | 不等于。它证明邮件服务接受提交；送达须在收件方验证。 |
| 来信变化时，旧回复怎么办？ | 已接受提交的正文单独保留；新通知更新并重新打开同一卡，旧回执不能完成新版。 |
| 演示会覆盖真实邮箱状态吗？ | 分开文件保存；真实状态绑定宿主账号，演示不继承真实规则。旧版未绑定账号数据保留、不自动导入。 |
| 桌面卡片有什么内容？ | 待确认数量与打开知信入口，含固定标题；无正文、地址或模型输出。 |
| 是否同步系统日历？ | 当前只有应用内日程板。 |
| 没有模型还能用吗？ | 使用规则识别并明确标注；能力有限，不能把规则结果当作真实模型输出。 |
| 覆盖全部邮件和所有连续事项吗？ | 每次同步最近 10 封；合并依赖发件地址与事项标题一致。更早历史、标题漂移仍需核对。 |
| 新版已经提交了吗？ | 当前为 0.3.8；查看公开 Release 和 #106 确认发布及受理状态，公开发布不代表进入已冻结评分。 |

## 最新现场状态与替代讲稿

0.3.8 已在官方 RC6 安装，知信保留 QQ 连接、显示最近 10 封真实来信；旧规则重算后待确认 4→0。本轮固定文本模型检查显示未就绪，不能说这些来信经过模型分析。自发测试邮件已打开宿主审阅，用户批准后宿主提示 Mail 未登录，未取得接受回执，不能说真实发送已完成。宿主 Mail 配置正在恢复。

完整收发尚未通过时，三分钟画面必须明确分段：前 30 秒展示实际收件与规则来源，随后切到标注的内置演示展示同卡演进和日程，末尾展示连接诊断与现存限制。不能在真实收件画面和演示确认之间剪辑出实际发送成功的印象。

建议答辩补充：“我们优先减少误待办。通知页脚和旧引用不会单独触发回复；物流未来和否定状态不会当成已完成。显示模型、规则、缓存来源，未知事实留给人核对。连接诊断还将邮箱读取、模型响应、发送接受、实际送达分开核对。”

当前 77 项回归与 21 页原生验证验证软件行为，不是模型准确率。更早邮件的重复主题缺少可证明的顺序时分别保留，手工草稿可在原文区域查看；不猜先后，也不声称覆盖全邮箱。
