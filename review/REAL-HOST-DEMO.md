1. 使用 macOS 上支持第三方应用 `mail.review_send` 的 OctoSense desktop RC2 或更新宿主。记录实际版本、源码 SHA、机器平台、启动方式与知信包摘要；不要只写“最新版本”。RC1/beta.2 不能完成第三方应用发送。

4. 宿主配置模型提供方，确保知信获准使用邮件账号。模型不可用时展示规则兜底，不能把规则结果写成真实模型结果。

## 测试来信与结果核验

由用户从测试发件箱发送以下两封通知到知信绑定的测试邮箱。日期按当天实际安排填写，避免使用历史演示日期。

第一封，主题“学校接孩子时间调整”：

> 您好，今天接孩子时间由 16:00 调整为 15:30，地点为学校北门。请回复确认新的安排。

第二封，同一发件人且相同主题：

> 补充通知：今天接孩子时间由 15:30 调整为 15:20，地点仍为学校北门。请回复确认最终时间。

| 步骤 | 操作 | 必须看到的结果 |
| --- | --- | --- |
| 来信 | 打开知信、同步收件箱 | 显示测试来信，无“演示数据”标记 |
| 模型与来源 | 打开提案，核对正文 | 对比与原文一致；记录是否为真实模型或规则兜底 |
| 后续变化 | 同步第二封通知 | 同一事项更新同一张提案，最终时间为 15:20；再次同步不回退旧版本 |
| 桌面卡 | 查看宿主桌面 | 卡片显示待确认数量，点按打开知信；不含正文或地址 |
| 编辑 | 修改回复为“已收到，今天 15:20 到学校北门接孩子。” | 草稿显示修改后的内容 |
| 取消 | 点击“审阅并发送回复”，在宿主取消 | 待办保留、草稿保留、不新增应用内日程、不宣称已发送 |
| 批准 | 再打开审阅，核对收件人/主题/正文，由用户批准 | 回执明确 accepted 后显示“已接受发送”，日程板和待办数更新 |
| 送达 | 在另一个测试邮箱打开回复 | 收件人、正文、发送时间一致；此项才证明实际送达 |
| 卡片变化 | 回到桌面 | 待办减少；全部处理完后卡片撤下 |
| 规则 | 记住同发件人同动作规则，再来新通知 | 规则已匹配，但仍待主动审阅，没有自动发送或连续弹窗 |
| 撤销 | 在规则页撤销，再来新通知 | 不再显示规则匹配，仍正常待确认 |

结果不明或网络错误时不自动重试；先核对已发送文件夹与收件方。请不要用重复点击尝试“强制成功”。

## 三分钟录像分镜

- 0:00–0:20：宿主版本、知信版本、测试账号说明。
- 0:20–1:00：真实来信 → 原文核对 → 后续通知更新同一提案。
- 1:00–1:40：修改草稿 → 宿主审阅 → 取消保留 → 再次审阅并由用户批准。
- 1:40–2:15：接受回执 → 收件方收到准确回复 → 应用内日程更新。
- 2:15–2:40：桌面卡待办数量变化与打开应用。
- 2:40–3:00：规则命中仍待审阅、撤销规则及失败状态说明。

使用真实连续录屏；如果剪辑，明确标注时间跳转，不把演示数据或模拟回执混入真实验收。
